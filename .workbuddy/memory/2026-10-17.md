## 修复 "Invalid Apple USB control response"（USB 控制通道）

- 根因：WinXPlay Windows 端走苹果旧驱动栈（接口 {f0b32be3} + USBAAPL64.sys 私有 IOCTL 0x2200A0）。本机 Apple Mobile Device Support 14.5.0.7 的 INF（AppleUSB.inf DriverVer 2023-06-14 538.0.0.0）早已把 iPhone mux 接口 MI_01 改绑 WinUSB（INF 原话 "New iTunes WinUSB interface"，注册 {664be590}）；注册表 Enum 里所有历史 MI_01 实例 Service=WINUSB，USBAAPL64.sys 虽在盘上但未绑定，DriverStore 无旧 INF。
- 修复：carplay/platform/windows/usb.cpp 增加 WinUsbControl 传输（WinUsb_Initialize + WinUsb_ControlTransfer，接口 GUID {664be590}），优先于旧路径；旧 USBAAPL64 IOCTL 路径保留作回退。用 #pragma comment(lib,"winusb.lib") 自包含链接，未改构建脚本。
- 重新编译通过，EXE 已导入 WINUSB.DLL。手机未接，待用户重连 iPhone（解锁+信任+数据线+直连主板口）实测后续阶段（NCM/IPv6、MFi 认证、TLS、媒体）。
- 排查辅助：E:/Python/python.exe carplay\tests\windows\usb_configuration.py 可分别测 WinUSB/legacy 两条控制路径并 dump 描述符（输出 build/carplay/windows-x64/usb-configuration.json）。

## error 50 (ERROR_NOT_SUPPORTED) 打开被拒（13:50 用户截图）
- WinUSB 接口 {664be590} 的 CreateFileW 返回 50。两个假设：H1 WinUSB 打开需 FILE_FLAG_OVERLAPPED（项目自带诊断脚本 usb_configuration.py 用的就是它，而我第一版修复用了 flags=0）；H2 苹果过滤驱动（AppleKmdfFilter/AppleUsbFilter）拒绝非 AppleMobileDeviceService 进程打开 WinUSB 接口（libimobiledevice 在现代 AMD Support 上的已知问题）。
- 旧版本从 legacy {f0b32be3} 链接能打开成功（卡在 IOCTL 阶段），两条链接指向同一设备对象。
- 已改为矩阵尝试：WinUSB 链接 × {同步, 重叠} → legacy 链接 × {同步, 重叠} → legacy IOCTL 0x2200A0，首个成功即用；失败报首次错误码。13:52 重建完成。
- 注意：本 app 依赖 AMD Service 的 usbmuxd(27015)（UsbMux），不能靠停服务来绕开（会破坏后续流程）。

## error 2 与决定性实验（14:05 用户截图）
- "Invalid Apple USB control response (error 2)"：error 2 很可能是假码——GetOverlappedResult 成功但 done 越界时 GetLastError 是残留值；WinUSB 对 USBAAPL64 私有 IOCTL 0x2200A0 很可能直接完成且返回 0 字节。已改为区分 "(transfer failed, error N)" 与 "(returned N bytes)"。
- IOCTL 尝试抛错会把前面的失败码又吞掉——已在所有传输失败消息后追加 "prior attempts: ..."（TransportReport::details）。
- 服务名确认：Apple Mobile Device Service（Running）。
- 给用户的决定性实验（不需重新编译）：①手机解锁+连接，先跑 usb_configuration.py 看 open_error；②管理员 Stop-Service "Apple Mobile Device Service" 后再跑；③Start-Service 恢复。若停服务后能读到描述符 → 过滤驱动按 AMD Service 是否运行门控（libimobiledevice 已知绕法），后续在 app 里做服务暂停/恢复之舞（需 UAC 提权）；若仍 50 → 按进程身份门控，需再想辙。另注意手机锁屏状态 itself 也可能被 AppleUsbFilter 门控（旧 USBAAPL64 栈锁屏时能开、传输失败；新栈未知）。
